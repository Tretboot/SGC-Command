Game-Loop

Der Herzschlag des Spiels: Basis → Mission → Ergebnis → Basis.

Der Zyklus #

BASE ──► MISSION_BRIEFING ──► COMBAT ──► DEBRIEF ──► BASE
 ▲                                                    │
 └────────────────────────────────────────────────────┘

Fünf Zustände, klar getrennt. Der Spieler wechselt zwischen der Basis → und dem Schlachtfeld →.

Die Phasen #

PhaseWas passiertSpieler-Input
BASEManagement: Räume bauen, Staff zuweisen, forschen, fertigen, Missionen annehmenVoll
BRIEFINGMission wählen, Team zusammenstellen (max. 6), AusrüstungVoll
COMBATTaktischer Grid-Kampf, AP-System, Gate-Timer läuftVoll (jede Aktion)
DEBRIEFErgebnis: Loot, XP, Verletzungen, Tote, Story-BeatLesen

End of Day #

Wenn der Spieler "Next Day" drückt, tickt die Basis automatisch:

  1. Produktion tickt: Workshop fertigt Items, Lab erzeugt Research-Points
  2. Staff tickt: MedBay heilt, Training gibt XP, Morale ändert sich
  3. Passive Income: +100 Credits, +20 Metal, +5 Deuterium
  4. Mission Alerts: 1–2 neue Missionen spawnen
  5. Tag += 1, Auto-Save
Wichtig 1 Mission = 1 Tag. Die Basis-Zeit ist während des Kampfs gefroren. Das hält den Rhythmus klar und vermeidet Echtzeit-Druck in der Basis.

State-Management #

Single Source of Truth, Reducer-Pattern, kein Framework:

// Alle Spiellogik = pure Funktionen
(state, action) → newState

// Kein DOM-Zugriff in der Logik → testbar + serialisierbar
const state = {
  meta:  { version: 1, day: 1, phase: 'BASE', seed: 12345 },
  base:  { grid, rooms, staff, resources, research, production, power },
  mission: { type, mapSeed, tiles, units, round, phase, gateHp }
};

Save-System #

  • JSON.stringify(state) → localStorage['sgc_save_v1']
  • Save-Points: End of Day, nach Debrief, manuell
  • Inklusive Mission-State → Save & Quit mitten im Kampf möglich
  • meta.seed für reproduzierbare procedural Maps
