Art-Toolchain

Wie man Assets generiert, testet und integriert. 100% prozedural – keine Bilddateien, kein drawImage in art2.js.

Die harte Grenze art2.js verwendet nur fillRect (hartkantig, pixel-art). arc, ellipse, drawImage sind verboten – sonst bricht der Raster-Test (er misst nur fillRect).

Die drei Tests #

1. Raster-Test (Headless)

cd game && node ../incoming/rastertest.js

Ersetzt fillRect durch ein Pixelarray-Raster (1000×860 RGB). Prüft:

  • Out-of-Bounds: zeichnet eine Funktion außerhalb ihres Sprite-Bereichs?
  • Negative Rechtecke: fillRect mit w<0 oder h<0
  • Determinismus: Seed 7 = Seed 7, Seed 7 ≠ Seed 8
  • Self-Test: ruft art2SelfTest() auf

Erwartet: selftest bad: [] und out-of-bounds/neg issues: none

2. Browser-Gate-Test

node test-browser.js

Simuliert echten Browser-Start: alle 7 Skripte in <script>-Reihenfolge, load-Event, Frame-Loop, DOM-Prüfung. Jeder Durchgang muss damit grün sein.

3. Preview (Visuell)

incoming/preview.html im Browser öffnen (braucht art.js + art2.js im selben Ordner). Zeigt: Feind-Gesichter, Waffen, Raum-Icons, benannte Charaktere, Rekruten (Seed-Input zum Durchblättern), Terrain-Kachel-Test.

Neue Assets generieren #

Rekruten

const reg = registerRecruit(200, 'fighter');
// reg = {seed, name, cls, look, dossier, age}
// LOOKS[reg.name] und DOSSIERS[reg.name] sind jetzt gefüllt
// portrait({name: reg.name, cls: reg.cls}) funktioniert sofort

Seed-Regel: Projekt nutzt Seed 100–123. Neue Rekruten ab Seed 200 aufwärts. Ab ~100 Rekruten: Kollisions-Check.

Feind-Typen

Neuen case in drawEnemyFace (art2.js). Konvention: 32×32, Hintergrund #14202e/#1b2b3d. Test: drawEnemyFace(c, 'neuerTyp', 0, 0, 1) in rastertest.js.

Waffen

Neuen case in drawWeapon. Konvention: 32×16, Seitenansicht nach rechts. Anzeigename in _A2WNAME eintragen.

Raum-Typen

Neuen case in drawRoomIcon. Konvention: 32×32, Hintergrund #0f1622 + Rahmen #243248.

Terrain-Themes

Neues Theme in _A2TH + Theme-Branches in drawTile. Konvention: 48×48, nahtlos kachelbar (Rauschen an Weltkoordinaten, Muster-Perioden 8/12/16/24 teilen 48).

Benannte Charaktere

In Object.assign(LOOKS, {...}) (art2.js, Sektion 4.1). Felder: skin, hair, style, optional: glasses, beard, goatee, scar, band, mark (bool oder Farbstring), crown, glow, stars.

Integration ins Spiel #

Script-Reihenfolge (index.html)

<script src="sound.js"></script>
<script src="art.js"></script>      ← LOOKS, shade(), drawFace
<script src="art2.js"></script>     ← NACH art.js (nutzt shade(), LOOKS)
<script src="engine.js"></script>   ← NACH art2.js (ruft registerRecruit beim Parsen)
<script src="combat.js"></script>
<script src="base.js"></script>
<script src="ui.js"></script>

Warum: engine.js baut den POOL beim Parsen auf (24×registerRecruit), also muss art2.js schon geladen sein. art.js referenziert Engine-Globals nur zur Laufzeit → keine Zirkularität.

Tile-Cache (Performance)

drawTile braucht ~600 Hash-Aufrufe pro Boden-Tile. Ohne Cache: 300 Tiles × 600 = 180.000 Calls pro Frame. Mit Cache: 5 Tiles einmal in ein Offscreen-Canvas, dann drawImage pro Tile. Code in renderCombat (combat.js), C.tileCache pro Mission-Start. Nicht entfernen.
